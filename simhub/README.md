# teamradio56 — SimHub 플러그인 (C# 포팅)

파이썬 단독 앱의 판단 로직을 C#으로 옮긴 SimHub 플러그인.
**플러그인은 항상 C# 내장 엔진 하나로 돈다 — SimHub만 켜면 판단/콜과 영어 무전이 kokoro 음성 팩
한 목소리로 나온다 (파이썬 불필요).** 0.18부터 경량판: 파이썬 엔진 모드, edge 온라인 목소리,
Windows 음성, 목소리 섞임 허용, LLM 설정, 한국어 무전을 플러그인에서 뺐다 (설정 화면은 한국어/영어 그대로).
음성 팩이 없으면 무전은 소리 없이 자막·최근 무전에만 나가고, 설정 화면이 [음성 팩 업데이트]를 누르라고 알린다.
저장소 루트의 파이썬 앱은 레퍼런스 구현(리플레이 회귀의 기준)이자 음성 팩 렌더 도구로 남는다.

SimHub은 호스팅(자동 실행 / 설정 UI / 배포)만 담당하고, 텔레메트리는
**공유 메모리에서 직접 읽는다.** LMU 전용 필드(덴트 존, 충격 크기,
pathLateral, 횡속도, 블루 플래그, 섹터 플래그, FCY 피트 오픈 상태)가 SimHub
정규화 계층에는 없기 때문 — 즉 포팅해도 기능 손실이 없다. 다른 게임으로
넓힐 때만 SimHub 정규화 데이터를 소스로 추가한다.

### 텔레메트리 원천 (LMU 내장 메모리 우선, rF2 DLL 대체)

`Core/Telemetry/TelemetrySource.cs`가 매 틱 원천을 고른다 (플러그인 Tick이 쓰는
`Poll()`/`Connected`는 예전 리더와 같은 모양):

1. **LMU 내장 공유 메모리 `LMU_Data`** (LMU 1.2+, 게임 설정 Settings → Gameplay → Enable Plugins +
   재시작) — `LmuNativeReader` + `LmuNativeLayout`. 쓸 만하면(열림·gameVersion > 0·차량 수
   범위·값 검증·5초 안 갱신) 이것. rF2 DLL이 이번 실행에서 살아 있으면(스코어링 버전이 움직임)
   Extended 버퍼에서 거기 없는 세 필드(피트 제한속도, 상태/히스토리 메시지)만 보충. 멈춘 매핑은
   5초 뒤부터 2초마다 닫았다 다시 열어 게임 종료(Absent)를 알아챈다 (핸들을 쥐면 매핑이 안 사라짐).
2. **rF2 Shared Memory Map Plugin** (`Rf2SharedMemoryReader`) — DLL만 있는 사용자는 동작이 같다.
   버전 규칙(`VersionLiveness`): 처음 본 버전·5초 넘게 못 보다 다시 본 버전은 기준값. 내장을 쓰는
   동안에도 버전만 따라가고, 내장이 멈춰서 내려놓으면 rF2가 그 뒤 실제로 움직여야 넘어간다.
3. 둘 다 없으면 "게임 대기".

내장 메모리 레코드는 rF2 V01 레코드와 크기·앞부분이 같아서, 필요한 범위만 복사해 기존 rF2
구조체로 마샬링하고 기존 `SnapshotBuilder`에 넣는다 — 분석기가 보는 값의 단위·의미가 구성상
같다. 레이아웃 출처·읽기 규약(찢김 감시 재읽기)·가드·빈 필드·확인 안 된 것은
[docs/DATA_SOURCES.md](../docs/DATA_SOURCES.md#lmu-내장-공유-메모리-lmu_data), 기계가 읽는 명세는
[docs/lmu_native_layout.json](../docs/lmu_native_layout.json).
원천이 바뀔 때마다 로그에 `텔레메트리 소스: …` 한 줄, 설정 화면 상태 램프 아래에
"데이터: LMU 내장 공유 메모리 / rF2 공유 메모리 플러그인 (DLL)"이 나온다.

## 구조

```
TeamRadio56.Core      SimHub 무관한 순수 로직 (텔레메트리/설정/진단, 앞으로 분석기·멘트·TTS)
TeamRadio56.SimHub    얇은 플러그인 래퍼 (IPlugin/IDataPlugin/IWPFSettingsV2) + 설정 UI
```

Core가 SimHub을 참조하지 않으므로, 같은 Core로 나중에 단독 exe도 뽑을 수 있다.

### 컴파일 검증

**개발 환경에서도 전체 C#을 컴파일 검증한다** (SimHub 설치 불필요):

```bash
bash simhub/verify/build-check.sh
```

`verify/*.Stub`이 SimHub 인터페이스의 최소 스텁을 만들고, 그걸 참조해
Core와 플러그인을 빌드한다. 문법·타입·오탈자·시그니처 오류를 전부 잡는다.
LMU 내장 메모리 명세(`docs/lmu_native_layout.json`) 자체 검사(`tools/lmu_native_blob.py verify-spec`)도
여기서 돈다. 경량판 가드도 함께 돈다: 뺀 기능(System.Speech, edge 클라이언트, mp3 재생, 파이썬 엔진 호스트,
한국어 멘트 풀 등)이 소스에 다시 들어오면 실패하고, 설정 화면 문자열(Loc.cs)의 ko/en 키가 같은지,
음성 팩이 없을 때의 안내가 [음성 팩 업데이트]를 가리키는지 확인한다.
**못 잡는 것은 실제 SimHub API와의 차이뿐** — 스텁이 곧 그 API에 대한
가정이므로, 가정이 틀리면 사용자 PC 빌드에서 드러난다.

그 외에도 실패 지점을 줄여뒀다:

- 구조체는 손으로 옮기지 않고 `rf2data.py`에서 **자동 생성** + 런타임 크기 대조
- 설정 UI는 **XAML 없이 코드로 조립** (x:Class 매칭, .g.cs 생성 실패 제거)
- 메뉴 아이콘은 **.resx 리소스 없이** base64 PNG를 코드에 내장
- 설정 저장은 외부 JSON 라이브러리 없이 **key=value 파일**

## 빌드

**필요한 것**: .NET SDK 8 하나뿐. Visual Studio도, .NET Framework 개발 팩도
필요 없다 (net48 참조 어셈블리를 NuGet으로 받도록 설정돼 있음).

```powershell
winget install Microsoft.DotNet.SDK.8     # 없으면 한 번만
# PowerShell 새로 열고
cd D:\teamradio56\simhub
dotnet build -c Release
```

winget이 없으면 https://dotnet.microsoft.com/download/dotnet/8.0 에서
**SDK x64** 설치 파일을 받는다.

SimHub이 기본 경로가 아니면:

```powershell
dotnet build -c Release -p:SimHubPath="D:\SimHub"
```

## 업데이트 (설정 화면에서 — 사용자)

0.16부터 플러그인이 **GitHub 릴리스에서 직접 업데이트**한다. 저장소·빌드 도구가
필요 없다.

1. SimHub → teamradio56 설정 화면 맨 아래 **업데이트** 섹션
2. **[업데이트 확인]** → 현재 버전 / 최신 버전, 설치된 음성 팩 / 최신 음성 팩이 보인다
   ("시작 시 확인"이 켜져 있으면 하루 한 번 SimHub 시작 15초 뒤 **확인만** 자동으로 한다.
   새 버전이 있으면 화면 위에 안내가 뜬다)
3. **[플러그인 업데이트]** → 끝나면 **SimHub을 재시작**해야 적용된다
4. **[음성 팩 업데이트]** (설치된 팩이 없거나 팩이 바뀐 릴리스에서 켜짐, 약 175 MB) → 끝나면
   엔진이 자동으로 다시 시작해 바로 적용된다 (안 되면 [엔진 재시작])

**음성 팩이 없으면**(새 설치, 팩 폴더를 지움, 설치가 중간에 끊김) 무전은 소리 없이 자막·최근 무전
(`(무음)` 표시)·`LastRadio` 프로퍼티에만 나간다 — 다른 목소리로 대신 읽지 않는다. 설정 화면 맨 위에
빨간 안내가 뜨고, "시작 시 확인"이 켜져 있으면 하루 주기와 무관하게 시작 15초 뒤 확인을 돌려
[음성 팩 업데이트]를 바로 누를 수 있게 한다.

설치는 **버튼을 누르고 확인 창에서 [예]를 눌렀을 때만** 한다. 받는 동안 진행률이
보이고 [취소]할 수 있다.

**안에서 일어나는 일**

- 릴리스마다 붙는 `teamradio56-release.txt`(버전, zip 이름, sha256)를
  `https://github.com/hyungwookc07/teamradio56/releases/latest/download/` 에서 받는다.
  GitHub API·로그인을 쓰지 않으므로 호출 제한도 없다.
- 플러그인: zip 받기 → **sha256 검증** → 두 DLL이 다 있는지 확인 → 작업 폴더에 풀기 →
  실행 중인 `TeamRadio56.*.dll`을 `.old`로 **이름만 바꾸고**(로드된 DLL은 덮어쓸 수는
  없어도 이름은 바꿀 수 있다) 새 DLL을 넣는다. 중간에 하나라도 실패하면 바꾼 이름을
  전부 되돌리므로 **반쯤 설치된 상태는 남지 않는다.** `.old`는 다음 SimHub 시작 때 지워진다.
- 음성 팩: zip을 **전부 받고 sha256을 확인한 뒤에야** 오디오 캐시에 푼다. 오디오 캐시
  폴더의 `teamradio56_audio_pack.txt`가 설치된 팩 이름이다 (중간에 끊기면 "설치 미완료"로
  보이고 다시 받을 수 있다). 표식 없이 조립 자산 4개(`_seg1_*.wav`)만 있으면 손으로 넣은
  `kokoro-v015`로 본다 — 0.17은 `kokoro-v016`을 쓰므로 이 사용자에게 [음성 팩 업데이트]가
  켜진다. 받기 전까지 v016에만 있는 멘트는 자막으로만 나간다 (다른 목소리로 읽지 않는다).
- 받는 중 임시 파일은 SimHub 폴더의 `teamradio56_update\`(쓸 수 없으면 `%TEMP%`)에
  두고, 다음 시작 때 정리한다.

**처음 한 번은 손으로**: 0.15 이하에는 업데이터가 없다. 릴리스 페이지에서
`teamradio56-plugin-x.y.z.zip`을 받아 두 DLL을 SimHub 폴더에 복사하거나(SimHub 종료 후),
소스가 있으면 아래 `update.bat`을 쓴다. 그 다음부터는 설정 화면에서 된다.

| 메시지 | 원인/조치 |
|---|---|
| 인터넷에 연결할 수 없습니다 | 오프라인·방화벽·프록시. 시스템 프록시 설정을 그대로 쓴다. 안 되면 릴리스 페이지에서 직접 받기 |
| 릴리스 파일을 찾을 수 없습니다 | 새 릴리스를 막 올리는 중이거나 아직 업데이터 릴리스가 없음 — 잠시 후 다시 |
| 폴더에 쓸 권한이 없습니다 | SimHub 폴더가 쓰기 금지 (보통은 플러그인이 설정·로그를 쓰는 폴더라 괜찮다). SimHub을 한 번 관리자 권한으로 실행해 업데이트하거나 직접 복사 |
| 받은 파일이 손상되었습니다 | sha256 불일치 — 기존 플러그인은 그대로다. 다시 시도 |

화면에는 원인 분류만 나오고 자세한 내용(URL, 파일 이름, OS 오류)은 `teamradio56.log`에 남는다.

### 되돌리기 (.old)

업데이트 뒤 SimHub을 켰는데 플러그인이 안 뜨면(새 DLL이 로드조차 안 되면 정리가
돌지 않아 `.old`가 남아 있다):

1. SimHub 종료
2. SimHub 폴더의 `teamradio56_backup.txt`를 연다. 업데이터가 DLL마다 실제로 백업한
   파일 이름을 `백업 파일 -> 원래 이름` 줄로 적어 둔다. 예:
   ```
   TeamRadio56.Core.dll.old1 -> TeamRadio56.Core.dll
   TeamRadio56.SimHub.dll.old -> TeamRadio56.SimHub.dll
   ```
3. 각 줄마다 오른쪽 파일(새 DLL)을 지우고 왼쪽 파일을 오른쪽 이름으로 바꾼다
4. SimHub 시작, `teamradio56.log`를 알려주세요

`.old` 번호로 짐작하지 말 것: 지우지 못한 묵은 `.old`가 있으면 비어 있는 다음 번호
(`.old1`, `.old2`…)에 백업하므로 번호 없는 `.old`가 직전 버전이라는 보장이 없고, 번호는
DLL마다 다를 수 있다. 기록 파일이 없으면 탐색기에서 수정한 날짜를 본다 — 이름을 바꿔도
빌드 시각이 그대로라 같은 버전의 두 DLL은 몇 초 차이로 붙어 있다. 지금 DLL보다 오래된
것 중 가장 최근의 **짝**을 고른다. 다른 버전끼리 섞으면 플러그인이 뜨지 않을 수 있다.
플러그인이 정상으로 뜨면 시작할 때 `.old*`와 기록 파일을 지운다.

설정 화면에 **"되돌리기 실패"**가 뜨면(DLL 교체 도중 실패했고 원래대로 돌리지도 못한
경우) 플러그인 폴더에 새 DLL과 이전 DLL이 섞여 있을 수 있다. **SimHub을 재시작하기 전에**
화면(과 `teamradio56_backup.txt`)에 나온 파일을 위 3번처럼 바꾼다. 이 상태에선 같은
세션에서 플러그인 업데이트를 다시 하지 못하게 막아 둔다.

`.old`가 이미 지워졌으면 릴리스 페이지에서 이전 버전 zip을 받아 두 DLL을 복사하면 된다.
업데이터는 **더 높은 버전만** 제안하므로 이전 버전으로 내려가는 건 이 수동 복사뿐이다.

## 업데이트 (소스에서 빌드 — 개발자)

저장소를 받아 직접 빌드해 쓰는 경우는 루트의 **`update.bat` 더블클릭** 하나로
끝난다 — pull, 빌드, SimHub 폴더 DLL 복사까지. (PowerShell 기본 보안 정책이
.ps1 직접 실행을 막으므로, bat이 이번 실행에 한해 우회해서 돌려준다.)

터미널에서 돌리려면:

```powershell
cd D:\teamradio56
.\update.bat                                        # 기본 경로 설치면 이대로
.\update.bat -SimHubPath "D:\SimHub"                # 다른 경로면
```

SimHub이 켜져 있으면 DLL이 잠기므로 스크립트가 종료를 기다렸다가 복사한다.

## 릴리스 만들기 (메인테이너)

릴리스는 **GitHub Actions가 만든다** (`.github/workflows/release.yml`). PC에 SimHub이
없어도 된다 — Windows 러너가 SimHub을 무인 설치(버전별 캐시)하고 그 실제 어셈블리로
빌드한다. 스텁(`verify/build-check.sh`)으로 빌드한 DLL은 배포하지 않는다.

**지금 상황**: `v0.17.0`은 GitHub 화면에서 손으로 만든 빈 릴리스다 (자산이 없어 설정 화면이
업데이트를 찾지 못한다 — 지워도 된다). **v0.17.1이 첫 실제 릴리스**로 게시됐다
(`release/v0.17.1` 브랜치 push, 새 음성 팩 `audio-kokoro-v016`을 같은 실행이 먼저 렌더·게시,
샤드 6개로 약 35분). 기술자는 `kokoro-v016`을 가리키고, 멘트 집합이 그대로면 다음 릴리스는
음성 팩을 다시 렌더하지 않는다. **v0.18.0**(`0.18.0-lite`, 경량 플러그인)은 영어 멘트 집합(통문장 1223 ·
문장 6214)이 그대로라 `kokoro-v016`을 그대로 쓰고 게시됐다. **v0.19.0**(`0.19.0-lite`)은 세션 브리핑 변형·체커 등급·체커 뒤 무전, 트래픽 클래스 호칭(LMP3 추가,
"faster car" 제거, 클래스 모르는 접근 예고)으로 멘트 집합이 바뀌어(통문장 1138 · 문장 7219, 트랙 이름
목록 제거) 같은 실행이 새 팩 `audio-kokoro-v017`을 먼저 렌더·게시하고 게시됐다 — 사용자는 그 팩을
받기 전까지 새 문장이 자막만 나간다. 다음 버전 `0.19.1-lite`(같은 클래스 차는 클래스 이름 없이)는
멘트 집합이 그대로라(통문장 1138 · 문장 7219) `kokoro-v017`을 그대로 쓴다 — 음성 팩을 다시 받을 필요 없음.

**한 단계로**: `TeamRadio56Plugin.Version` 숫자부와 같은 **`vX.Y.Z` 태그를 main에 있는 커밋에
push**하거나, **GitHub 화면에서 그 릴리스를 만든다** (Releases → Draft a new release → 새 태그
`vX.Y.Z`, Target `main` → Publish release — 제목·본문은 비워도 된다). 나머지는 워크플로가 한다:

```bash
git tag -a v0.17.1 -m "한 줄 요약"     # 주석 태그 첫 줄 = 설정 화면 '변경 사항' (화면에서 만들면 없음)
git push origin v0.17.1
```

1. **preflight** — 태그 = `v<Version 숫자부>`, 태그 커밋이 main에 있음, 공개된 플러그인
   릴리스(매니페스트가 있는 `vX.Y.Z`, 초안·프리릴리스 제외) 중 가장 높은 버전보다 높음
   (`releases/latest`는 보지 않는다 — 화면에서 만든 빈 릴리스가 latest여도 같다). 같은 태그
   릴리스가 이미 있으면 **화면에서 만든 빈 릴리스**(초안 아님, 자산 0개, 태그가 이 커밋)일 때만
   이어받는다 — 자산이 하나라도 있으면 실패. 그리고 `voice_lines/audio_pack.txt`의
   `audio-<pack>` 릴리스가 공개돼 있고 zip 이름·크기·sha256과 **지금 코드가 찾는 멘트 집합**이
   맞는지 본다. 기술자 tag가 `audio-<pack>`이 아니거나 멘트 집합이 다르면 **새 팩이 필요** — 새
   ID는 숫자 꼬리 +1(`kokoro-v015` → `kokoro-v016`, 이미 공개된 ID는 건너뜀). 기술자가 가리키는
   `audio-<pack>` 릴리스가 없거나 초안이면(preflight의 읽기 토큰엔 초안이 안 보여 둘을 가르지
   못한다), 또는 공개된 팩의 자산이 기술자와 다르면 새 팩을 렌더하지 않고 실패
2. **gates** — `build-check.sh` + `replay-check.sh` (`TEAMRADIO56_STRICT=1`)
3. **audio** (새 팩이 필요할 때만) — `audio-pack.yml`을 불러 렌더 → `audio-<pack>` 게시 →
   새 `audio_pack.txt`를 **main에 커밋** (아래 음성 팩 절)
4. **build** (Windows) — audio가 돌면 끝날 때까지 기다린다. SimHub 무인 설치
   (`simhub/ci/install-simhub.ps1`, zip sha256 고정) → `release.bat -Ci`로 실제 SimHub 빌드(참조
   어셈블리 버전 확인) → 플러그인 zip + 매니페스트 + 메타. 새 팩을 렌더했으면 그 실행의
   기술자로 만든다 (`-AudioPackFile`, 태그 커밋의 기술자는 옛 팩)
5. **verify-artifact** — 게시될 바로 그 파일로 사용자 업데이트 흐름 재현
   (플러그인 교체 + `audio-<pack>`에서 음성 팩 설치)
6. **publish** — 새로 만들면 `gh release create --latest`, 이어받으면 zip → 매니페스트 순으로
   올린 뒤 제목·본문·latest를 고친다. `releases/latest/download/teamradio56-release.txt`가 새
   버전을 가리키는지 확인. 쓰기 권한은 이 잡과 음성 팩 게시 잡에만 있다

- **태그를 push할 수 없을 때** (브랜치 push만 허용되는 자동화 등): main에 있는 커밋을
  **`release/vX.Y.Z` 브랜치로 push**해도 같은 흐름으로 게시한다 (`git push origin
  main:refs/heads/release/v0.17.1`). 브랜치 이름 = `release/v<Version 숫자부>`, 커밋이 main에
  있어야 하고 태그가 아직 없어야 한다 — 태그는 게시할 때 GitHub이 그 커밋에 만든다 (수동 게시와
  같은 길, 이어받기 없음). 설정 화면 '변경 사항' 한 줄은 그 커밋 메시지의
  `Release-Notes: 한 줄 요약` 트레일러 (메시지 마지막 문단 — `Co-Authored-By:` 같은 다른 트레일러와
  같은 묶음에 둔다. 따로 떨어진 문단이면 git이 트레일러로 읽지 않는다). 게시가 끝나면 브랜치는 지워도 된다. 실패해서 코드를
  고쳤으면 브랜치를 main 최신 커밋으로 다시 push한다 (태그는 게시 때만 생기므로 지울 것이 없다).
- 태그가 버전과 다르거나(예: `v0.17.1-rc1`) main에 없으면 실패한다 — 태그를 지우고
  (`git push origin :refs/tags/<태그>`) 맞게 다시 만든다.
- 화면에서 만든 릴리스는 실행이 끝날 때까지 빈 채로 latest라서 그동안 [업데이트 확인]은
  "릴리스 파일을 찾을 수 없습니다"가 된다. 저장소에서 변경 불가(immutable) 릴리스를 켰으면
  화면 경로는 쓸 수 없다 (공개된 릴리스에 자산을 더할 수 없다) — 태그 push를 쓴다.
- **실패하면** 플러그인 릴리스는 남지 않는다 (게시는 마지막 잡이고, 이어받기는 중간에 멈추면
  올린 자산을 지워 빈 릴리스로 되돌린다). Re-run은 **같은 태그 커밋**(그 커밋의 워크플로·
  스크립트)을 다시 돌린다 — 네트워크·권한·승인처럼 코드 밖 원인이면 원인을 풀고 실행 화면의
  **Re-run failed jobs** (게시한 음성 팩을 포함해 성공한 잡은 다시 돌지 않는다). **코드를 고쳐야
  하면** main에 고친 뒤 태그를 지우고(`git push origin :refs/tags/v0.17.1`) main 최신 커밋에 다시
  태그해 push한다 — 이미 게시한 음성 팩은 main의 기술자에 들어 있어 다시 렌더하지 않는다.
  화면에서 만든 릴리스였다면 그 빈 릴리스와 태그를 화면에서 지우고 main을 대상으로 다시 만든다
  (태그만 지우면 릴리스가 초안으로 남는다). 버전을 올려 새 태그를 만들어도 된다. Re-run all
  jobs는 쓰지 않는다: 새 팩을 게시한 뒤라면 preflight가 "main의 기술자가 바뀌었다"로 멈춘다
  (그때도 위처럼 main 최신 커밋에 태그를 다시 만든다).

**시험 빌드 (dry run)**: `release-dry/`로 시작하는 브랜치를 push하면
(`git push origin HEAD:release-dry/test`) 게시·음성 팩 렌더 없이 preflight → gates → Windows
설치·빌드 → verify-artifact까지 돌고 결과를 아티팩트로 받는다 (팩이 없거나 낡았으면 경고만 하고
지금 기술자로 빌드). Actions → release → Run workflow(`dry_run` 켠 채, 기본)도 같다. 다른 SimHub
버전은 Run workflow의 `simhub_version`으로 (새 버전은 zip sha256을 경고로 찍는다 — 확인 후
`install-simhub.ps1` 표에 더한다). `dry_run`을 끄면 main에서 태그 push 없이 게시한다 (태그는
GitHub이 그 커밋에 만든다, `notes`가 변경 사항, 같은 태그가 있으면 거부).

**캐시**: SimHub 설치본과 코코로 모델은 Actions 캐시에 둔다. 캐시는 ref별이라 태그 실행이
저장한 캐시는 다음 태그가 못 쓴다 — main에서 한 번 dry run을 돌려 데워 두면 이후 태그는
main 캐시를 쓴다.

### 음성 팩 — 전용 `audio-<pack>` 릴리스

음성 팩 zip(`kokoro-v016` 약 175 MB, 24 MiB 이하로 8개 안팎)은 플러그인 릴리스에 올리지 않는다. 팩마다 한 번 **`audio-<pack>`
프리릴리스**(latest가 되지 않는다 — `releases/latest`는 항상 플러그인 릴리스)에 올리고,
`voice_lines/audio_pack.txt`가 그 태그와 zip 이름·sha256·크기를 가리킨다. 플러그인
릴리스의 매니페스트는 `audio_tag`로 그 주소를 가리키기만 한다.

```
pack=kokoro-v016
tag=audio-kokoro-v016
asset=teamradio56_kokoro_v016_1of7.zip,<sha256>,<바이트 수>
...
```

- **멘트 집합이 바뀔 때만** 새 팩. 보통은 릴리스 실행이 알아서 만든다(위 3단계 — 기술자는
  main에 커밋). 따로 만들려면 Actions → **audio-pack** → Run workflow, `pack`에 **새 ID**
  (예: `kokoro-v020`) — 기술자는 **실행한 브랜치에 커밋**. 어느 쪽이든 렌더 전 게이트(샤드 분할
  검사 포함) → 코코로 모델(sha256 고정) → 통문장·세그먼트를 샤드 6개로 병렬 렌더(약 1.5~2시간)
  → 샤드 캐시 합치기 → `tools/pack_audio.py`로 24 MiB 이하 zip 분할 → 렌더 후 게이트(실캐시
  100% + 팩 설치 흐름) → `audio-<pack>` 초안 → 새 `audio_pack.txt` 커밋 → 프리릴리스로 공개.
  `dry_run`은 렌더·zip·아티팩트까지만. 이미 공개된 팩 ID는 거부한다 (남은 초안은 지우고 다시).
- 팩 ID가 바뀐 사용자에게만 [음성 팩 업데이트]가 켜진다. 배포된 ID는 그 멘트 집합에 묶인다
  (`pack_audio.py`가 집합 해시로 확인 — `kokoro-v015`처럼 다른 집합에 배포된 ID를 쓰면 거부).
- 멘트가 바뀌었는데 팩이 그대로면 게시 실행은 새 팩을 먼저 렌더하고, dry run은 경고만 한다
  (그대로 내면 빠진 멘트는 자막으로만 나간다).
- **`audio-*` 릴리스는 지우거나 자산을 바꾸지 말 것** — 매니페스트가 sha256으로 고정하고
  있어 모든 사용자의 음성 팩 업데이트가 깨진다.
- zip 업로드 중에 실패하면 초안을 지운다 — publish 잡만 다시 실행하면 된다 (렌더는
  아티팩트를 그대로 쓴다). 기술자 push 뒤 공개에서 멈췄어도 publish 잡 재실행이 커밋 없이
  공개만 한다.
- 기술자 커밋·push가 막히면(보호 규칙 등) **초안은 남긴다** (사용자에겐 안 보인다). 손으로
  마무리: 아티팩트 `teamradio56-audio-<pack>`의 `audio_pack.txt`를 그 브랜치의
  `voice_lines/audio_pack.txt`로 커밋·push → `gh release edit audio-<pack> --draft=false
  --prerelease --latest=false`. 또는 원인을 풀고 publish 잡만 다시 실행 (남은 초안은 지우고
  다시 올린다). 이미 **공개된** `audio-<pack>`이 있으면 그 팩 ID로는 다시 내지 않는다.

### 필요한 저장소 설정

- Actions 사용, 워크플로 권한은 기본(읽기)이어도 된다 — 잡마다 필요한 권한을 적어 두었다
- audio-pack이 `github-actions[bot]`으로 기술자를 push한다 (단독 실행은 실행 브랜치, 릴리스
  실행은 main). main에 보호 규칙이 있으면 github-actions 우회를 허용하거나, 위 '손으로
  마무리'대로 기술자 커밋과 초안 공개를 손으로 한다 (기술자만 옮기고 초안을 공개하지 않으면
  release preflight가 거부한다)
- (선택) Environment `release`에 Required reviewers를 걸면 게시 잡마다 승인을 받는다
  (릴리스 실행 안의 음성 팩 게시도)
- 변경 불가(immutable) 릴리스를 켜면 화면에서 만든 릴리스는 이어받지 못한다 — 태그 push로

### 대체 경로 — `release.bat` (실제 SimHub이 있는 Windows PC)

Actions를 쓸 수 없을 때. 필요한 것: .NET SDK 8, 실제 SimHub, 있으면 편한 GitHub CLI
(`winget install GitHub.cli` → `gh auth login`). 커밋을 push한 뒤 저장소 루트의
**`release.bat` 더블클릭** (또는 옵션과 함께):

```powershell
.\release.bat -Notes "한 줄 요약 — 설정 화면 '변경 사항'에 그대로 보인다"
.\release.bat -SimHubPath "D:\SimHub"                 # SimHub이 다른 경로면
.\release.bat -NoPublish                              # 파일만 만들고 손으로 올릴 때
.\release.bat -AudioDir "D:\packs"                    # 예전 방식 기술자(tag=이번 v태그)일 때만
```

버전 읽기 → 게시된 최신보다 높은지 → 실제 SimHub으로 `Release` 빌드 → 두 DLL zip·sha256 →
`audio_pack.txt`로 매니페스트 → `dist\release\<x.y.z>\` → gh가 로그인돼 있으면 게시
(커밋 push 여부, 같은 릴리스·태그 없음, `audio_tag` 릴리스의 zip 이름·크기 확인), 없으면
새 릴리스 페이지와 결과 폴더를 열고 올릴 파일을 안내한다 ("Set as the latest release" 켠 채).
Actions는 같은 스크립트를 `-Ci`(멈춤·게시 없음, `-OutDir`·`-MetaDir`·`-ExpectTag`·`-NotesFile`)로 부른다.

게시 후 확인: `https://github.com/hyungwookc07/teamradio56/releases/latest/download/teamradio56-release.txt`
가 새 버전을 보여주는지, 그리고 SimHub에서 [업데이트 확인].

### 매니페스트 형식 (`teamradio56-release.txt`)

UTF-8 `key=value` 줄, `#` 주석, 모르는 키는 무시 (뒤 버전이 키를 추가해도 앞 버전이
깨지지 않는다). 형식을 깨는 변경은 `format`을 올린다 — 모르는 format을 받은 플러그인은
"릴리스 페이지에서 직접 받으세요"라고 안내한다.

| 키 | 예 | 의미 |
|---|---|---|
| `format` | `1` | 형식 버전 |
| `version` | `0.17.1` | 숫자 x.y.z — 플러그인 `Version`의 숫자부와 비교 |
| `tag` | `v0.17.1` | 이 릴리스 태그 |
| `plugin_asset` / `plugin_sha256` | `teamradio56-plugin-0.17.1.zip` / 소문자 hex | 두 DLL zip |
| `audio_pack` | `kokoro-v016` | 음성 팩 ID (설치된 표식과 다르면 업데이트 제안) |
| `audio_tag` | `audio-kokoro-v016` | 팩 zip이 올라가 있는 릴리스 태그 |
| `audio_assets` / `audio_sha256` / `audio_size` | 콤마 구분, 같은 순서 | 팩 zip들 (`audio_size`는 선택 — 다운로드 전 크기 표시) |
| `notes` | 한 줄 | 설정 화면 "변경 사항" (선택) |

### 잘못된 릴리스를 냈을 때

- **아직 아무도 안 받았으면**: GitHub에서 그 릴리스를 지우거나 pre-release로 바꾸면
  `latest`가 이전 릴리스로 돌아간다 (`audio-*` 음성 팩 릴리스는 지우지 말 것).
  같은 버전으로 다시 내려면 **태그까지** 지운다 — 웹에서 릴리스만 지우면 태그가 남고,
  다시 만든 릴리스가 그 태그(예전 커밋)에 붙는다:
  `gh release delete v<x.y.z> --repo hyungwookc07/teamradio56 --cleanup-tag`
  (이미 릴리스만 지웠으면 `git push origin :refs/tags/v<x.y.z>`). 남아 있으면 스크립트가 멈춘다.
  Actions로 다시 낼 때도 같다 — 태그를 지운 뒤 다시 push한다. 화면에서 만든 빈 릴리스면 그
  릴리스와 태그를 함께 지우고 다시 만든다 (태그만 지우면 릴리스가 초안으로 남는다).
- **음성 팩 릴리스가 latest가 됐으면**: `gh release edit <v태그> --latest` 로 플러그인
  릴리스를 되돌리고 `gh release edit audio-<pack> --prerelease --latest=false`.
- **audio-pack이 기술자는 커밋했는데 공개에 실패했으면**(초안으로 남음): 그 실행의 Re-run
  failed jobs(공개만 이어서) 또는 `gh release edit audio-<pack> --draft=false --prerelease
  --latest=false`. 그 전까지 release preflight가 게시를 거부한다.
- **이미 받은 사용자가 있으면**: 업데이터는 내려가는 버전을 제안하지 않으므로 고친
  버전을 **더 높은 번호로** 다시 낸다. 플러그인이 아예 안 뜨는 사용자는 위
  [되돌리기 (.old)](#되돌리기-old)로 직전 버전을 살린다.

### 검증

`verify/replay-check.sh`는 LMU 내장 공유 메모리 리더도 검사한다: `tools/lmu_native_blob.py pack`이
명세만 보고 합성 `LMU_Data` 덤프·같은 상태의 rF2 버퍼·기대 스냅샷을 만들고, 러너
`--lmu-native-dump`(실제 리더)와 `--rf2-dump` 출력을 대조한다 (C# 오프셋 실수를 C# 코드와 독립적으로
잡고, 두 원천이 같은 스냅샷을 내는지 확인). `--lmu-native-selftest`는 원천 선택·대체 규칙(매핑 없음,
gameVersion 0, 차량 수 범위 밖, 크기 부족, 찢긴 읽기, 멈춤, 게임 종료 — 핸들이 매핑을 살려 둔 채
내용이 멈춤 → 닫고 Absent → 재시작 시 가드 초기화, 차량 0대, 플레이어 슬롯, 값 검증 래치·다시 판정,
Extended 보충(멈춘 DLL이면 안 함), 멈춘 rF2로 넘어가지 않기, 설정 화면 상태 줄 키)을 돈다.

`verify/replay-check.sh`가 릴리스 도구도 검사한다: 음성 팩 기술자와 매니페스트를 Core
파서(`ReleaseManifest`)로 대조하고, pwsh가 있으면 `ps-check.ps1`로 Windows PowerShell 5
호환(파싱, 7 전용 문법, BOM)을 본 뒤 `release.ps1`을 검증 모드(`-TestDllDir`, 빌드·게시
없음)로 돌려 그 결과 폴더를 릴리스 서버처럼 내놓고 사용자 업데이트 흐름(확인 → DLL 교체 →
`.old` 정리)을 그대로 재현한다. `TEAMRADIO56_AUDIO_DIR`에 팩 zip 폴더를 주면 음성 팩 설치까지
돈다(`--audio-dir`로 `audio-<pack>` 릴리스 자리에서 설치). 리눅스에 pwsh가 없으면
`dotnet tool install -g PowerShell`.

`release.ps1 -Ci` 검증 모드(메타 파일·태그 대조·한글 요약 파일, `-AudioPackFile`, 태그 불일치가
멈춤 없이 실패하는지)와 `tools/pack_audio.py selftest`(분할 경계·zip 이름·기술자 갱신·verify
거부·다음 팩 ID)도 돈다. `verify/release-flow-check.sh`는 release 워크플로 스크립트를 가짜
gh/curl/git으로 돌려(네트워크 없음) 게시·이어받기·dry run 판단, 새 음성 팩 필요 여부와 ID,
음성 팩 게시(기술자 커밋·재실행), 플러그인 게시 호출 순서를 확인한다. CI는 환경 변수로 더 엄격하게 돌린다:

| 변수 | 뜻 |
|---|---|
| `TEAMRADIO56_STRICT=1` | pwsh·numpy/soundfile이 없어 건너뛰던 검사를 실패로 |
| `TEAMRADIO56_REQUIRE_CACHE=1` | `audio_cache/*_rfx3.wav`가 없으면 실패 (실캐시 Resolve 필수) |
| `TEAMRADIO56_AUDIO_DIR=폴더` | 음성 팩 zip 폴더 — `release.ps1 -AudioDir` 대조 + 팩 설치 흐름 |

## 설치

두 DLL을 **SimHub 설치 폴더 루트**에 복사한다 (하위 폴더 아님):

```powershell
copy src\TeamRadio56.SimHub\bin\Release\net48\TeamRadio56.*.dll "C:\Program Files (x86)\SimHub\"
```

SimHub을 재시작하면 첫 실행 시 **"새 플러그인을 활성화할까요?"** 창이 뜬다 →
teamradio56 체크. (안 뜨면 SimHub → Settings → Plugins에서 수동 활성화.)

활성화되면 SimHub **좌측 메뉴에 "teamradio56"** 항목이 생긴다.

## 파이썬 단독 앱과 함께 쓰지 않기

플러그인은 0.18부터 파이썬 엔진을 띄우지 않는다 (예전 `python` 엔진 모드는 없어졌다 — 설정 파일에
남은 `EngineMode=python`, `EngineExe`, `EngineArgs` 같은 키는 무시되고 다음 저장 때 지워진다).
저장소 루트의 파이썬 앱(`main.py`)은 레퍼런스 구현·음성 팩 렌더 도구이고, LLM 멘트·섹터 피드백·
한국어 무전·edge 목소리 같은 실험 기능도 거기에만 있다. 플러그인과 **동시에 돌리지 않는다** —
둘 다 무전을 내므로, 단독 앱은 플러그인이 쥔 뮤텍스(`Local\teamradio56-plugin`)를 보면 스스로
물러난다. Steam 시작 옵션의 `launch_with_lmu.bat`도 지운다.

## 이번 단계에서 확인할 것

1. 빌드가 통과하는가
2. SimHub 좌측 메뉴에 **아이콘과 함께** teamradio56이 뜨는가
3. 설정 화면이 그려지고, 값을 바꾸면 설정 파일에 반영되는가
4. [테스트 발화] 누르면 소리가 나는가 (음성 팩이 없으면 "음성 팩이 없어 무음 — [음성 팩 업데이트]")
5. 음성 팩이 없을 때 맨 위 빨간 안내 → [음성 팩 업데이트] → 끝나면 안내가 사라지고 소리가 나는가
6. LMU를 켜면 상태 램프가 초록으로 바뀌고 **실제 값**(트랙/순위/연료/속도)과
   최근 무전이 보이는가 — 그리고 **실제 콜이 들리는가**

**로그 파일**: SimHub 폴더의 `teamradio56.log` — SimHub 로그 API에 의존하지
않는 독립 채널이라, 플러그인이 로드만 되면 무조건 기록이 남는다.

기대 로그:
```
==== teamradio56 0.9.0-simhub-engine 시작 ====
설정 파일 없음 — 기본값 사용 (...\teamradio56.settings.txt)
구조체 레이아웃 검증 통과 (Telemetry 241680B / Scoring 75312B / Extended 10152B)
LMU 내장 공유 메모리 레이아웃 검증 통과 (LMU_Data 324820B, 최대 104대)
초기화 완료. 로그: ... / 설정: ...
목소리: kokoro 음성 팩 (상태 ok)
내장(C#) 엔진 — 분석기 9종, 영어 무전. 음성 팩 폴더: ...\audio_cache (팩 kokoro-v016, 무전 효과본 1223개, ...)
초기화 완료. 로그: ... / 설정: ...
SimHub 게임 이름: 'LMU'            ← 실제로 뭐라고 나오는지 알려주세요
LMU 내장 공유 메모리(LMU_Data) 갱신 감지 — gameVersion 원시값 …   ← 이 숫자도 알려주세요 (인코딩 미확정)
텔레메트리 소스: LMU 내장 공유 메모리 (LMU_Data, gameVersion=…) — rF2 DLL 불필요
LMU 내장 공유 메모리 값 검증 통과 (플레이어 mID 일치, 타이어 온도·공기압·마모 정상)
```

내장 메모리가 없으면 `텔레메트리 소스: rF2 공유 메모리 플러그인 (DLL) — LMU_Data: 없음 (…)` 또는
`텔레메트리 소스: 없음 — 게임 대기 (…)`가 남는다. 값 검증이 실패하면 `WARN LMU 내장 공유 메모리
값 검증 실패 — …`에 사유(예: 타이어 온도 몇 K)가 붙는다 — 그 줄을 그대로 붙여주세요.

**출시 전 실차 확인(아직 못 함):** LMU 1.2+에서 rF2 DLL을 깐 채로 세션에 들어간다. 내장 메모리를 쓰는
중에 DLL 버퍼도 있으면 값 검증 통과 약 5초 뒤 한 번 두 원천의 스냅샷을 대조해 `교차 확인: LMU 내장 공유
메모리 = rF2 DLL 버퍼 …`(일치) 또는 `WARN 교차 확인: … 다름 N건 (내장/rF2) — …`(필드별 두 값)를 남긴다
(`SnapshotCompare`, 진단 전용 — 엔진에는 내장 스냅샷만 간다). 연속값은 갱신 주기 차이를 감안한 허용
오차로 비교한다.

음성 팩이 없으면 `목소리: kokoro 음성 팩 (상태 none — no-kokoro)`와
`음성 팩이 없어 무전을 소리 없이 자막·최근 무전에만 냅니다 — 설정 화면 [업데이트] → [음성 팩 업데이트]`가 남는다.

**빌드 에러나 화면 이상은 그대로 붙여주세요.** 제가 컴파일 확인을 못 하는
환경이라, 에러 메시지가 유일한 피드백 채널입니다.

### 예상되는 걸림돌

| 증상 | 원인/조치 |
|---|---|
| `SimHub을 찾을 수 없습니다` | `-p:SimHubPath="실제경로"` 로 지정 |
| `IWPFSettingsV2를 구현하지 않습니다` / 멤버 불일치 | SimHub 버전별 API 차이. 에러에 나온 멤버 이름을 알려주세요 (플러그인 파일 상단 3개 프로퍼티만 고치면 됨) |
| `'GameData'에 'GameName' 정의가 없습니다` | 진단용 로깅일 뿐 — `_loggedGameName` 블록을 통째로 주석 처리 가능 |
| `dotnet: 명령을 찾을 수 없음` | SDK 설치 후 PowerShell을 새로 열어야 PATH가 잡힌다 |
| 설정 화면 글자가 안 보임 | SimHub 테마와 색 충돌 — 알려주시면 색을 테마 상속으로 바꿉니다 |
| 로그에 `구조체 레이아웃 불일치` | 생성기 문제 — 출력된 크기를 알려주세요 |
| 계속 "게임 대기" (DLL 없이) | LMU 1.2 이상인지, Settings → Gameplay → Enable Plugins를 켜고 게임을 **완전히 재시작**했는지. 로그 `텔레메트리 소스:` 줄의 `LMU_Data:` 사유를 확인 (없음 / gameVersion 0 / 값 이상 / 갱신 없음). 안 되면 rF2 DLL을 설치하면 그쪽으로 읽는다 |
| 로그에 `LMU 내장 공유 메모리 값 검증 실패` | 게임 업데이트로 레이아웃이 바뀐 듯 — 그 매핑은 쓰지 않고 rF2 DLL로 대체한다. 경고 줄(사유·gameVersion)을 알려주세요 |
| 플러그인 목록에 안 보임 | DLL을 SimHub **루트**에 뒀는지 확인, SimHub 재시작 |
| 아무 콜도 소리가 안 남 / 맨 위에 빨간 음성 팩 안내 | 음성 팩이 없거나 설치가 끊겼다 — [업데이트] 섹션의 [음성 팩 업데이트] (꺼져 있으면 먼저 [업데이트 확인]). 끝나면 엔진이 자동으로 다시 시작한다. 예전 파이썬 엔진 모드에서 엔진 실행 파일·`main.py` 옆에 둔 캐시는 더 이상 자동으로 찾지 않는다 — [음성 팩 업데이트]로 DLL 옆에 새로 받거나 **음성 팩 폴더**에 그 경로를 넣는다 |
| 최근 무전에 `(무음)`이 붙음 / 콜이 자막으로만 나감 | 음성 팩에 없는 멘트라 다른 목소리 대신 침묵한 것 (목소리를 섞지 않는다). 로그 `teamradio56.log`의 `[무음]` 줄에 이유가 있다 — `kokoro-miss`(음성 팩에 없는 멘트 → [음성 팩 업데이트], 그래도 남으면 알려주세요), `no-pack`(음성 팩 폴더 없음 → [음성 팩 업데이트]), `play-failed`(오디오 장치) |
| 뒤차 클래스를 이상하게 부름 / 클래스 이름 없이 "Traffic behind"만 나옴 | 내 클래스와 같은 클래스의 차는 원래 클래스 이름 없이 부른다 ("Car behind.", 랩 돌리러 오는 클래스 리더는 "Traffic behind, …"). 다른 클래스인데 이름이 없으면 게임이 주는 클래스 문자열을 계열(Hypercar/LMP2/LMP3/GTE/GT3)로 못 묶은 것 — 모르는 클래스는 이름 없이 부르고, 베스트 랩이 2% 넘게 빠를 때만 접근 예고한다. 로그 `teamradio56.log`의 `클래스 진단:` 줄(세션마다 처음 본 클래스 문자열 → 계열·서열·호칭, 내 클래스)을 붙여주세요 |
| 소리가 두 번 들림 / 목소리가 겹침 | 파이썬 단독 앱(launch_with_lmu.bat)이 같이 돌고 있다 — 단독 앱은 플러그인을 감지하면 물러나지만, 플러그인을 쓴다면 Steam 시작 옵션의 launch_with_lmu.bat은 지우세요. 그래도 겹치면 작업 관리자에서 python.exe/teamradio56.exe가 남아 있는지 확인 |

## C# 내장 엔진 — 포팅 현황

**판단 계층은 포팅 완료**: 이벤트 버스(쿨다운/우선순위/TTL), 상태(랩
히스토리/베이스라인), 분석기 9종(트래픽·스포터/레이스컨트롤/차량상태/
연료/페이스/타이어/라이벌/전략/리포터), 세션 브리핑, 멘트 풀(자동 생성),
보이스 워커 + 음성 팩 재생(통문장 클립 + 문장 세그먼트 조립).

**한 목소리 정책**: 목소리는 kokoro 음성 팩 하나뿐이다. 엔진 시작 때 팩 상태를 한 번 확인하고
(로그 `목소리: kokoro 음성 팩 (상태 …)`) 모든 콜을 팩의 클립으로 말하거나 아예 말하지 않는다.
말하지 않은 콜도 로그 `[무전] 텍스트`, 최근 무전(`(무음)` 표시), `LastRadio` 자막에는 남는다.

- 음성 팩 설치됨(`ok`) → 팩에 있는 멘트는 말하고, 팩에 없는 멘트는 자막만 (다른 목소리로 읽지 않는다)
- 설치가 중간에 끊겼지만 팩 확인용 통문장(pit_call 첫 줄)이 남아 있음(`partial`) → 남은 클립만 말하고
  나머지는 자막만 — 설정 화면이 [음성 팩 업데이트]를 다시 실행하라고 경고
- 팩 없음(`none`) / 설치가 끊기고 확인용 통문장도 없음(`incomplete`) → **세션 전체 무음(자막만)**.
  폴더에 다른 클립이 남아 있어도 재생하지 않는다 (발화 경로가 팩 상태로 막힌다, 사유 `no-pack`).
  설정 화면 맨 위 빨간 안내와 상태 블록이 [음성 팩 업데이트]를 누르라고 알리고, [테스트 발화]도 같은 안내
- 세션 브리핑은 트랙 이름 없이 항상 "Radio check."로 열고, 세션 종류(연습·퀄리·웜업·레이스, 시작/중간
  합류)마다 다르게 구성한다. 연습·퀄리·웜업은 차가 트랙에 나가 있을 때만 중간 합류다 — 진행 중인
  세션에 차고(피트)에서 붙으면 아웃랩·"준비되면 나가" 쪽 시작 구성에 길이만 남은 시간으로. 문장
  슬롯마다 변형 2~5개 중 하나를 스냅샷 값(브리핑 시점 세션 시계·노면 온도·연료 등) 시드의 FNV-1a
  해시로 고른다 — 해시의 상위 비트로 줄여(`(h × n) >> 32`) 슬롯끼리 독립이고, 파이썬과 같은 문장,
  세션마다 다른 문장
- 체커 콜은 결과 등급(우승·클래스 우승·포디움·스타트 대비 상승/비슷/하락·중간 합류)마다 변형이 있고
  실제 클래스 순위를 말한다 (예전엔 8위로 잘렸다). 체커 뒤에는 쿨다운 랩(아직 달리는 차·빠른 클래스
  경고) → 요약 한 번(베스트 랩의 클래스 순위) → 피트인(리미터·차고) 순으로 이어가고 (ESC로 차고에
  순간이동하면 피트인 콜은 말없이 넘긴다), 내 피니시 뒤엔
  전략·연료·타이어·라이벌·순위·정기 리포트를 끈다 (피트 리미터·옐로·휠 탈락·나란히/빠른 차 접근만 남긴다)
- 팩 상태 판정(`ok`/`partial`/`incomplete`/`none`)과 사유(`no-kokoro`/`pack-incomplete`/`pack-partial`)는
  파이썬 `tts.kokoro_pack_state`/`resolve_voice_kind`의 kokoro·en 행과 같다 — 파이썬 단독 앱이 팩 없이
  edge로 대신 말하는 자리가 플러그인에서는 무음이다 (replay-check가 결정표와 팩 상태 픽스처로 대조)

**리플레이 회귀로 파이썬과 동작 일치가 검증된다**:

```bash
bash simhub/verify/replay-check.sh
```

파이썬 하니스(tools/replay_calls.py)와 C# 러너(tests/TeamRadio56.Replay)에
같은 녹화(data/replays/*.jsonl.gz)를 먹여 "버스가 수락한 이벤트"를
순서·타이밍·데이터까지 비교하고(변형 풀 콜은 랜덤 문장 대신 고른 풀·슬롯 `voice` — 클래스 호칭·갭),
사전 캐시 멘트 전체 집합(en 1138개)과
문장 세그먼트 집합(단계 1~3, 7219개), 세그먼트 조립 출력 바이트도
diff한다. 클래스 정규화(tools/class_check.py ↔ 러너 `--class-check`)는 실제 LMU 클래스 문자열
후보 약 60개의 계열·서열·호칭, 클래스 쌍마다 같은 클래스·빠른 클래스(관측 페이스 포함)·무전 호칭, 진단 로그
문장, 페이스 중앙값을 바이트 단위로 대조한다. 세션 시작 브리핑도 양쪽 러너가 첫 틱에 내보내 문장을 대조한다 (대조는 en만 —
플러그인 무전이 영어 고정이다. 파이썬 단독 앱의 한국어는 같은 게이트의 "파이썬 전용 ko 스모크"가
멘트 풀·퍼즈 규칙·리플레이 실행만 확인한다).
리플레이마다 en 발화가 전부 통문장 클립이나 문장 세그먼트로 나가는지도 확인한다
(`--coverage --tier 3 --min 100`, 미스면 빠진 문장을 출력). 커버리지 퍼즈
(tools/coverage_fuzz.py ↔ 러너 `--fuzz-eval`)는 분석기의 발화 판단 함수와 순수 조립 함수에
도메인 안팎 값 약 36만 건을 넣어 가상 음성 팩으로 판정하고 파이썬 ↔ C# 결과를 대조한다
(억제 규칙이 한쪽 엔진에서만 빠져도 불일치로 드러난다).
`race_end_*` 리플레이는 체커 뒤 30초(피트인 시나리오는 75초)까지 가는 짧은 합성 레이스로, 규칙대로
계산한 정답(`.truth.json`)과 마지막 랩·체커 콜(등급·스타트 순위·상승 계단), 체커 뒤 무전(쿨다운 랩·
요약·피트인), 피니시 뒤 침묵(허용 목록 밖 콜 0), 남은 랩 트레이스(`--race-end-trace`, 모든
리플레이에서 파이썬 ↔ C# 대조)를 tools/race_end_oracle.py가 대조한다 (`race_end_pitin.config.json`은
두 하니스가 읽는 설정 덮어쓰기 — 리포터를 켠다. `race_end_garage*`는 체커 뒤 ESC 차고 복귀).
`session_*` 리플레이(연습·퀄리·웜업, 시작·중간 합류·차고 합류)는 브리핑 문장 전체를 기대 콜
(`.expect.json`)과 대조하고, tools/radio_flow_selftest.py가 변형 도달성·슬롯 독립성·골든 브리핑·
체커 등급 규칙·피니시 뒤 침묵을 단위로 확인한다
(생성기 tools/make_race_end_replays.py, 게이트는 `--check`로 재생성 대조).
`rival_pit`은 경쟁자 피트 콜 경우를 한 레이스에 모은 합성 리플레이다 — 포메이션·카운트다운
중 피트, 처음 볼 때 이미 피트에 있는 차, 틱 공백(직후 기록이 5초 안 되는 뒤차 포함), 순위 0,
랩 다운 차, 첫 랩·FCY 피트, 차고 순간이동, 내가 피트에 있거나 아웃랩일 때 따라 들어온 뒤차는
침묵하고 그린/FCY 앞차 피트와 그린 중 바로 뒤차 피트만 콜한다. 앞/뒤는 진입 전 5초 순위 기록으로
정해서 진입 틱 순위 맞바뀜이나 진입 감속 중 몇 틱 먼저 추월당한 앞차도 앞차로 콜한다.
기대 콜(`.expect.json`)과 파이썬·C# 수락 콜을 각각 tools/expect_calls.py가 대조한다 — 두 엔진이
같이 틀리면 파이썬 ↔ C# 대조만으로는 못 잡는다 (생성기 tools/make_rival_pit_replay.py, `--check`).
`align`은 얼라인(조향 쏠림) 콜 경우를 한 레이스에 모은 합성 리플레이다 — 직선·고속 스위퍼(200km/h,
전부 오른쪽, 조향 최대 0.17)가 섞인 랩에서 멀쩡한 차가 스위퍼 직전에 가볍게 부딪히면 침묵(예전 EMA
감지와 요레이트 게이트 없는 중앙값은 한쪽으로 쏠린 스위퍼 조향을 읽어 오탐), 피트 아웃 직후 기준 없는 충격·펑크로 인한 쏠림도 침묵, 직선 조향 오프셋 +0.05는 경미·+0.10은
심각 콜 하나. `align_rebase`는 1랩 첫 직선의 기준 없는 접촉 뒤에도 다음 충격의 손상(+0.05)을 경미로
콜하고(기준 없는 충격은 그 충격만 — 기준을 다시 모은다), `align_crab`은 리어 토 손상으로 비스듬히
곧게 가는 차(직선 횡속도 1~2.5m/s)의 +0.05·+0.10을 경미·심각으로 콜한다. `align_gate`는 멀쩡한 차가
메인 직선 접촉 뒤 같은 직선에서 게이트 하나만 어기는 틱 — 슬라이드(횡속도 4.2m/s, 카운터 −0.15)와 플랫
굽이(요레이트×속도 3m/s², 조향 +0.06) 각 6초 — 를 달려도 침묵해야 하고, 생성기는 요레이트·횡속도
게이트 중 하나만 빼도 판정이 바뀌는지 확인한다 (리플레이 하니스는 버스를
비우지 않아 같은 키 콜이 리플레이마다 한 번이라 나눴다). 샘플은 곧게 가는 순간(요레이트×속도 ≤
1.5m/s², 횡속도 ≤ 3m/s — 슬라이드만 뺀다)만, 기준은 첫 충격 전 최근 101개(최소 25) 중앙값, 판정은
충격 뒤 51개가 찼을 때 중앙값이다. 두 엔진은 판정마다
진단 로그 한 줄(기준·충격 후 중앙값·샘플 수·변화·결정)을 남긴다 (생성기 tools/make_align_replay.py,
`--check`; 사이드카 `keys`로 align_damage/align_severe 콜만 대조). `align_report`는 판정이 점검 리포트
쿨다운 안이라 대기 중인 경미 콜과 두 번째 충격(첫 리포트 +15.4초) — 그 충격의 점검 리포트가 먼저 나가고
대기 콜은 그 리포트 쿨다운 뒤, 두 번째 충격이 펑크를 남기면 대기 콜은 피트까지 붙든다 (b60e335는 대기
콜이 쿨다운 끝 틱에 나가 두 번째 리포트 — 펑크·박스 — 를 잃었다; 사이드카 `keys`에 점검 리포트 포함).
`wing`은 프론트 윙(스플리터 높이) 콜 경우를 모은 합성 리플레이다 — 높이가 속도²(300km/h에서 22mm)와
브레이크 다이브(3mm/g)로 움직이는 랩(느린·중속·긴 고속 구간, 2g대 제동)에서 멀쩡한 차가 중속 구간
출구에서 가볍게 부딪히고 긴 직선을 달리면 침묵(예전 EMA 감지는 여기서 "Front aero down 10
millimetres" 오탐), 필드가 정적(상수)인 차·펑크로 내려앉은 높이도 침묵, 메인 직선 접촉의 실제 손상
(h0 −15mm)은 콜 하나 — 구간은 몇 초 만에 차지만 판정은 점검 리포트 뒤, 콜은 리포트 쿨다운 20초 뒤
재시도로. `wing_rebase`는 1랩 첫 직선의 기준 없는 접촉 뒤 멀쩡한 접촉(기준을 굳히고 침묵), 다음 랩
실제 손상(첫 기준 유지, 새 판정 버퍼)을 콜한다. 샘플은 피트레인 밖·150km/h 이상·직전 두 틱 감속
≤ 0.5g, 속도 구간 floor((v−150)/10), 기준은 첫 충격 전 최근 301개(5샘플 이상 구간 3개 미만이면 그
충격만 판정 없음), 판정은 충격 뒤 양쪽 5샘플 이상 구간이 3개가 되는 첫 틱에 구간별 중앙값 차의
중앙값 ≥ 10mm다. 두 엔진은 판정마다 진단 로그 한 줄(맞춘 구간·샘플 수·하락·결정)을 남긴다 (생성기
tools/make_wing_replay.py, `--check`; 사이드카 `keys`로 wing_damage 콜만 대조). `wing_report`는 같은
대기 콜 규칙을 윙 콜로 확인한다 (대기 중 두 번째 충격 첫 리포트 +16초 — 점검 리포트 먼저, 펑크면 붙듦;
`keys`에 점검 리포트 포함).
`traffic_class_*`는 트래픽 클래스 판정 합성 리플레이 일곱 개다 — 내가 `Hyper`일 때 같은 `Hyper`·LMP2·
LMP3·LMGT3가 뒤에서 붙어도 접근 예고 없이 근접 콜만(호칭 없음/LMP2/LMP3/GT3, 예전엔 `Hyper`가
"faster car", LMP3는 빠른 차), `LMP3`일 때 `Hyper`는 접근 예고·LMGT3는 아님·앞 LMGT3는 백마커,
`LMP2`일 때 같은 랩 `LMP2_ELMS`는 배틀·한 랩 앞선 `LMP2_ELMS`는 랩핑 접근 예고, 계열 모르는 클래스는
베스트 랩 중앙값이 2% 넘게 빠르면 클래스 이름 없는 접근 예고(`traffic_approach_any`)·느리면 백마커·
페이스가 없으면 둘 다 아님. 내 클래스와 같은 클래스(같은 계열 포함)의 차는 클래스 이름 없이 부른다 —
`single`(LMP3 단일 클래스: 근접·나란히·지나감·떨어짐·랩 다운 백마커가 전부 이름 없는 변형, 랩 돌리러
오는 클래스 리더는 `traffic_approach_any`, 두 대는 "two cars behind."), `mixed`(LMP3 + LMGT3가 같이:
"one car, one GT3 behind."), `meet`(같은 계열 `LMP3_ELMS`와 앞 LMGT3가 같은 틱에 나란히: "car on your
right.", 떨어짐 호칭 GT3). 기대 콜은 변형 풀의 풀·슬롯(`voice`)과 다중 종합 문장까지 대조해 호칭을
확인한다 (v0.19.0 코드는 같은 클래스를 내 클래스 이름으로 불러 두 엔진 다 실패; 생성기
tools/make_traffic_class_replay.py, `--check`).
`sector_yellow_*`는 섹터 로컬 옐로 합성 리플레이 아홉 개다 — 원시값 1만 옐로, 직전 샘플이 옐로 아님 →
1인 엣지에서만 콜(LMU는 깨끗한 섹터가 11이라 예전 '0 이하 → 1..2' 규칙으론 콜이 한 번도 안 나갔다),
버스가 거절한 엣지는 섹터가 1인 동안 다시 시도, 섹터 콜을 쉬는 건 FCY(페이즈 6)뿐.
`lmu`(11 → 1 콜 하나, 1로 남은 동안 반복 없음 — ET 되감기로 대기 키를 비워 확인), `join`(첫 샘플에
이미 켜진 섹터는 침묵), `rf2`(rF2식 0 → 1은 그대로 콜), `junk`(2·7·255·0·-1 사이 전이는 침묵, 255·-1·2
→ 1은 콜 — -1은 원시 JSON이라 C# 로더는 255로 읽는다), `fcy`(FCY 동안 전 섹터 1이어도 침묵, FCY 진입
전 쿨다운에 걸린 빚은 FCY가 지움, 끝난 순간 1로 남은 섹터도 침묵, 리스타트 준비 중 새 옐로는 콜,
FCY·피트 오픈·그린 콜도 대조), `restart`(FCY 동안 깨끗하던 섹터가 리스타트 랩에 1 → 바로 콜),
`gate`(그린에서 옐로 상태 255·7·1·2여도 콜, 페이즈 6이면 옐로 상태 0·255여도 침묵), `cooldown`(같은 섹터
120초는 수락된 콜 기준 — 쿨다운에 거절되고 말 못 한 엣지는 기록 안 함), `double`(같은 틱 두 섹터는 낮은
번호 먼저, 1로 남은 다른 섹터는 종류 쿨다운이 풀리면 콜). 생성기는 예전 규칙이면 rf2 말고는 결과가
달라진다는 것, 직전 규칙과 억제 조건·기록 시점·재시도 변이 하나하나를 어느 리플레이가 잡는다는 것도
확인한다 (생성기 tools/make_sector_flag_replays.py, `--check`).
`race_end_restart`는 같은 세션에서 ET만 되감아 두 번 달린다 — 러너는 상태가 리셋되면
버스 대기열을 비운다(라이브 워커는 이전 레이스 콜을 진작 다 꺼냈다).
C# 멘트 풀(`PhraseLines.Generated.cs`, en만)이 voice_lines와 같은지는
`tools/gen_csharp_phrases.py --check`로 따로 확인한다.
분석기를 고치면 파이썬을 먼저 고치고 이 회귀로 C#을 맞춘다.

**파이썬 단독 앱에만 있는 것** (플러그인에는 없다):

- LLM 멘트 (전략 판단/브리지 후속/디브리핑) — 플러그인은 lap_analysis 등을 템플릿 폴백으로만
- 한국어 무전, edge·ElevenLabs 목소리, 목소리 섞임 허용(`tts.allow_fallback`)
- 트레이닝(섹터 코치/트랙 히스토리), REST 보조 소스, 레이스 JSON 저장

설정 파일에 예전 키(`EngineMode=python` 등)가 남아 있어도 플러그인은 항상 내장 엔진으로 돈다.
음성 팩은 DLL 옆 `audio_cache\`, 그다음 예전 설치의 `teamradio56-engine\audio_cache\`에서 자동으로
찾고(설정 **음성 팩 폴더**가 있으면 그것), 어디에도 없으면 [음성 팩 업데이트]가 DLL 옆 `audio_cache\`에 설치한다.

파이썬 버전(저장소 루트)은 레퍼런스 겸 실차 튜닝용, 그리고 음성 팩을 렌더하는 도구로 유지한다 —
버그는 파이썬에서 먼저 잡고 회귀로 C#을 따라오게 하는 게 빠르다.

### 배포 오디오 캐시 (`audio_cache\`)

영어 kokoro 팩은 두 층이다(`kokoro-v016` 약 175 MB — 통문장 1223 + 세그먼트 6214 + 조립
자산 4; 다음 팩은 통문장 1138 + 세그먼트 7219 + 조립 자산 4). 런타임 순서:

- 통문장 클립(효과본) → 문장 세그먼트 조립 → 효과 전 원본(개발 캐시) → **무음(자막만)**
- wav만 재생한다 — 예전 버전이 캐시에 남긴 edge mp3는 쓰지 않는다

| 파일 패턴 | 내용 | 만드는 명령 |
|---|---|---|
| `*_rfx3.wav` | 통문장 (무전 효과 적용, 8kHz PCM16) — 멘트 풀 + 소수 조합 멘트 | `python tools\pregen_audio.py --engine kokoro` |
| `*_seg1.wav` | 문장 세그먼트 (무전 효과 적용, 8kHz μ-law) — 숫자 슬롯 멘트용 | `python tools\pregen_audio.py --segments --tiers 1,2,3` |
| `_seg1_*.wav` | 조립 자산 4개 (클릭 / 간격 casual·urgent / 스켈치) | `--segments`가 마지막에 씀 |

- 배포 zip에는 위 세 패턴만 넣는다. 효과 전 원본 `*.wav`(이름이 md5 20자로
  끝나는 파일)는 재생성용이라 **배포하지 않는다**.
- 세그먼트는 멘트의 문장이 **전부** 있을 때만 쓰인다 (한 멘트 안에서 목소리가
  섞이지 않게). 빠진 문장은 SimHub 로그에 `코코로 문장 미스 [톤] 문장`으로
  처음 20건만 남고 그 콜은 `[무음]`(자막만)이 된다 — 그 문장을 사전 생성 도메인에
  추가하면 된다. 엔진 시작 때 팩에 없는 멘트 수를 세어 설정 화면에 보인다.
- 조립 자산이 없으면 세그먼트 조립은 통째로 꺼진다 (로그 `조립 자산 없음`).
- 세그먼트 렌더 규약(속도/효과/간격)을 바꿔 다시 배포할 땐
  `radio_assemble.SEG_VERSION`과 `VoiceCache.SegSuffix`를 함께 올린다.
- 대량 생성 전에 `--ab "멘트" --tone casual --ab-out ab`로 통문장/조립본을
  귀로 비교한다.

## 오버레이 (SimHub 프로퍼티)

플러그인이 Dash Studio/LED에서 쓸 수 있는 프로퍼티를 노출한다
(`TeamRadio56Plugin.이름`으로 보임). 무전 엔진과 별도로 공유 메모리에서
직접 계산되므로 스포터 표시가 5Hz로 즉답한다.

| 프로퍼티 | 타입 | 의미 |
|---|---|---|
| `LastRadio` / `LastRadioAgeSec` | string / double | 마지막 무전 텍스트 / 경과 초 (자막 페이드용) |
| `LastRadioDropped` | bool | 마지막 무전을 소리 없이 자막으로만 냈는지 (음성 팩에 없는 멘트, 또는 팩 없음) — 자막을 강조하는 데 쓴다 |
| `SpotterLeft` / `SpotterRight` | bool | 좌/우 나란히 (유령 차 필터 적용) |
| `NearestAheadM` / `NearestBehindM` | double | 앞/뒤 최근접 실존 차 거리 m (없으면 -1) |
| `GapAheadSec` / `GapBehindSec` | double | 동클래스 앞/뒤 시간 갭 (없으면 -1) |
| `Position` / `ClassPosition` | int | 전체 / 클래스 순위 |
| `HasDamage` / `HasFuelIssue` | bool | 진행 중 이슈 (경고 칩·LED 트리거) |
| `Connected` / `InSession` | bool | 상태 |
| `EngineMode` | string | 항상 `builtin` (예전 대시보드 바인딩 호환용으로만 남김) |

권장 오버레이 구성 (Dash Studio에서 10분 조립, 전부 선택식):

1. **무전 자막** — 하단 중앙 텍스트, `LastRadio` 바인딩,
   Visibility에 `[TeamRadio56Plugin.LastRadioAgeSec] < 6`
2. **스포터 바** — 화면 좌/우 가장자리 빨간 바,
   Visibility에 `SpotterLeft` / `SpotterRight`
3. **상태 칩** — 상단 `P[ClassPosition]`, `▲[GapAheadSec]s ▼[GapBehindSec]s`,
   `HasDamage`일 때만 DAMAGE 칩 표시

완성한 대시는 우클릭 → Export로 `.simhubdash`를 만들어 배포 zip에 동봉하면
유저는 더블클릭 임포트로 끝난다.
